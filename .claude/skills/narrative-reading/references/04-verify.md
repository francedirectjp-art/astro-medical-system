# 工程4 データ照合

**独立した工程として行う。執筆の続きでやらない。** 書いた本人が読み直しても、自分の文章は正しく見える。

役割は照合だけ。**文章を良くしない。**

## 照合するもの

生成された `.md` と、`chart8_<slug>.txt`（確定データ）を突き合わせる。

| 項目 | 見るところ |
|---|---|
| 天体の在室 | 本文の「◯◯は第Nハウス」がデータと一致するか |
| **サインとエレメント** | 特に**香りの章**。月が蠍座（水）なのに獅子座（火）と書いていないか |
| 進行天体 | 進行の月・太陽のハウスはネイタル重ねの値か |
| プロフェクション | 今年の年齢と領域。「◯歳から今この瞬間まで」型の誤りがないか |
| 接触 | 1度以内の接触が未来形で書かれていないか |
| 度数 | サビアンの度数が原文と対応しているか |
| 天体名 | **海アポロン星**のような破損がないか |

## 機械検品では拾えないもの

`check_reading.py` は正規表現なので、**文脈をまたぐ矛盾は原理的に拾えない**。実例。

```
本文    月は蠍座11度、天職の領域（正しい）
香りの章 月は火の性質を帯びた獅子座にあります（誤り）
```

香りはエレメントで調合が決まるので、**処方そのものが間違う**。物販に進むなら実害が出る。

この種の矛盾を見るのが工程4の存在意義。**ここを飛ばすと機械検品は合格するが中身は壊れている。**

## 手順

1. `chart8_<slug>.txt` の確定値を手元に置く（天体・サイン・ハウス・度数・エレメント）
2. 本文を通しで読み、天体名が出るたびに照合する
3. 相違があれば**本文を直す**（データは直さない）
4. 確定できない項目は「要確認」として明示し、勝手に断定しない

## 出所の区別

本文に書かれていることを三つに分けて扱う。

```
本人が書いた事実    三つの答えに書かれている経歴・構想
天体データ         計算で確定している配置
書き手の解釈       そこから立てた仮説
```

**本人の構想を、実現する未来として描かない。** 「そうなるでしょう」ではなく「そこへ向かう道に、この時期の風が吹いています」。応援と予測を分ける。

「生まれた日と時刻と場所のほかに何も知りません」と書いてはいけない。**三つの答えを受け取っている**ので事実として嘘になる。
